# depth of market beta · 1.1 完整简单使用说明

适用版本：**1.1**，程序集版本 **1.1.0.0**。本文介绍安装、参数和实际使用方法。

## 1. 先知道它在看什么

右边的盘口显示各价位的当前挂量；旁边的统计栏记录这段时间里挂量增加、减少了多少。开启密集区后，指标会用黄线圈出盘口活动异常或成交推进有限的位置，再继续观察这些位置的成交、补量和价格反应。

挂量减少既可能是撤单，也可能是成交消耗，单靠聚合盘口不能精确区分每笔减少的原因，更不能识别某个交易者。绿色、红色表示统计值的增加、减少，不直接表示做多、做空。

本版没有独立的买卖入场箭头。黄线是观察区域，不是承诺会反转的价位。

## 2. 安装前准备

- 使用 Windows 上兼容本 DLL 的 ATAS 或 ATAS X；本项目编译目标为 .NET 10 Windows。
- 平台需要连接对应合约的行情，并实际收到 Level 2 盘口和逐笔成交。行情源与订阅权限决定可观察的档位。
- 普通 ATAS 与 ATAS X 使用不同构建，不要混装。
- 本指标不需要激活码；平台账号、软件许可与行情权限仍按 ATAS 自身要求使用。

## 3. 安装与添加

1. 下载完整指标 ZIP 并解压，选择正确平台的 DLL。
2. 普通 ATAS 选择 `ATAS/DepthOfMarketBeta.dll`；ATAS X 选择 `ATASX/DepthOfMarketBeta.dll`。
3. 关闭平台后，将 DLL 复制到对应平台的自定义指标目录。普通 ATAS 常见目录是：

   ```text
   %APPDATA%\ATAS\Indicators
   ```

   可以把这一行粘贴到资源管理器地址栏。ATAS X 使用其自身的指标目录；不要直接假设它和普通 ATAS 共用目录。
4. 原目录已有同名 DLL 时，先复制到其他备份目录，再替换。不要同时放入同一指标的多个旧副本。
5. 启动平台，打开需要观察的合约主图，在指标列表搜索 **depth of market beta**，添加并应用。
6. 如果图上同时加载原生 Depth Of Market、旧版 Deltapex 或另一个 beta 实例，可能出现重叠。需要时移除重复实例。

已保存的模板可能覆盖代码默认值。想体验新的默认值，应重新添加且不套用旧模板，或在设置里手动核对。

## 4. 第一次怎么用

1. 先保持默认布局，确认右侧盘口随着行情变化。
2. 看 Net 和 Both 是否在出现新盘口变化后累计数值。刚加载的快照是基线，不算一次巨额增加。
3. 如果只需要原生盘口和挂撤单统计，可以一直保持 Z1 密集区功能关闭。
4. 要看黄线时，打开 **Z1. 密集区开关 → 启用密集区功能**。
5. 使用 GC、NQ、ES 时，可以先选择对应“品种起始参数”，再做手动调整。切换预设会重置区域参数和观察记录，建议先选预设再改细项。
6. 等待实时观察数据。盘口异常路径需要基线，通常要几十秒或更久；新价位还会单独预热。没有满足条件的区域时，不强制显示黄线。

## 5. 四个统计栏怎么读

假设同一个价位在本统计周期内先增加100手、再减少70手：

| 栏 | 显示什么 | 示例 |
|---|---|---|
| P1 Net 净额 | 增加减去减少 | +30 |
| P2 Stacked only 仅堆叠 | 累计增加 | +100 |
| P3 Pulled only 仅拉取 | 累计减少 | −70 |
| P4 Both 双向 | 同时显示增加与减少 | 左半−70、右半+100 |

四栏在每个价位按当前盘口侧记录。增加可能发生在买盘，也可能发生在卖盘；不要只看颜色猜多空。

统计清零时保留盘口基线，不会把仍在那里的全部挂量重新记成增加。首次加载、重连和重新计算可能重新建立基线。

### 默认布局和颜色

| 设置 | 默认值 |
|---|---|
| 原生 DOM 宽度 | 100像素 |
| Net 开关、距离 | 开启；150像素 |
| Both 开关、距离 | 开启；300像素 |
| 仅堆叠、仅拉取 | 默认关闭，可各自开启 |
| Net/Both 增加颜色 | #FF089981，青绿 |
| Net/Both 减少颜色 | #FFF2385A，红色 |
| Net/Both 文字颜色 | WhiteSmoke，接近白色 |

“距离”是这一栏的**右边缘距图表右侧**的像素数，数值越大越向左移动。它不是价格距离，也不是柱条宽度。

原生 DOM 的“宽度”控制原生挂量柱。1.1中独立栏没有开放可见宽度参数；其代码默认宽度为 Net/Stacked/Pulled 85像素、Both 150像素。

### P0—P4 参数说明

| 参数 | 简单说明 |
|---|---|
| P0 启用四个独立栏 | 开启后允许分别显示Net、堆叠、拉取、Both；关闭会清掉独立栏统计 |
| P0 共用重置周期（秒） | 供各栏继承；0随图表K线，正数为独立秒数 |
| 各栏“显示此栏” | 单独控制开关 |
| 距离（像素） | 各栏的位置，越大越向左 |
| 重置周期（秒） | -1继承P0；0随图表K线；正数为本栏独立周期 |
| 最小显示量 | 数值绝对值必须大于门槛才绘制，0会过滤零值 |
| 独立自动缩放 | 根据这一栏可见价位的统计值调节柱条长度 |
| 固定满宽对应量 | 关闭自动缩放后，多少量对应满宽；超过后不会无限伸长 |
| 显示数值、数字字号、文字颜色 | 控制累计量文字 |
| 增加颜色、减少颜色 | 按值的增减方向着色 |
| 柱条向左延伸 | Net/Stacked/Pulled的延伸方向；Both固定左减右增 |

### 重置周期的例子

- P0设0，Net与Both都设-1：两栏都随主图每根K线重置。
- Net设60、Both设300：Net每分钟清零，Both每5分钟清零，各自独立。
- Net设0、Both设300：Net跟随K线，Both按5分钟独立累计。

正数周期按 UTC 时钟对齐分段，是固定桶，不是滚动窗口。比如60秒桶在每个整分钟切换。图表显示的本地时区不会改变桶的切换。

修改某栏周期会清掉该栏累计，保留基线；修改P0只影响继承它的栏。重新计算或切换独立栏总开关会重建数据。周期参数不会改变黄线自己的秒数观察窗口。

## 6. 黄线为什么出现

总开关默认关闭。开启后，有两条形成路径，满足其中一条就可能出现区域。

### 路径A：盘口活动突然增多

默认把价格按4tick分组，分别观察买盘侧与卖盘侧。买一向下、卖一向上，最多扫描各80tick的变化；随最新报价移动。

80tick是价格距离，不是保证收到80档。GC对应8美元，NQ、ES对应20点。超出行情源实际推送范围的部分不可观察。扫描范围主要限制盘口事件采集，不会让已形成区域只因距离变远就立即删除。

一次增减至少达到以下两者中较大的值，才算合格变化：**2手、该档典型挂量的15%**。同一档事件计数至少间隔100毫秒；变化量仍按实际合格变化累计。

然后比较最近10秒和此前基线，需要至少30个有效基线观察秒，最近窗口至少12次事件、至少3个不同秒有活动，并且单位观察时间的事件速度达到基线的3倍。

基线按买卖侧、价格分组和距最佳报价的距离档分别建立。更远位置的安静基线不会直接拿来判断近端是否异常。新价位、新露出的盘口边缘和初始快照先作为基线，不立即解释成增挂爆发。

这条路径说明“这里活动异常密集”，还不证明这里一定守得住。

### 路径B：真实成交较多，但推进有限

默认开启“独立检测成交停顿区域”。在最近5秒中，需要攻击方向成交至少20手、至少3笔，占区内总成交至少65%，首末攻击成交相隔至少500毫秒，而沿攻击方向的最大推进不超过2tick。

例如：主动卖出较多，但价格向下推进很少，可形成买侧观察；主动买入较多但向上推进有限，可形成卖侧观察。未知方向成交进入总量，不假装成已知主动买卖。

所以有些黄线来自成交停顿，不要求先出现很多挂撤单。

## 8. 黄线出现后会跟踪什么

指标继续看价格是否进入、区内主动买卖量、攻击方向推进、成交后补量、离开后再次进入，以及是否持续越过不利边界。

默认匹配成交后800毫秒内的同价位补量。一笔攻击成交最多获得一次补量观察；同侧观察中，达到最少攻击量、笔数、攻击占比、至少2次补量和成交停顿等条件，才进入吸收观察状态。不能确认补量来自同一个人或同一个订单。

### 回测次数

首次进入算第一次访问。离开区域至少3tick、达到1000毫秒的离开确认后，再次进入才开启新一轮。图上的“第几次回测”是后续重新进入的轮次，不是成功守住的次数，也不是胜率。

成交窗口会滚动，旧成交到期后不继续当作当前证据。行情过期或价差异常时暂停相应判断。

### 失守与删除

通用规则：沿不利方向**严格超过**区域边界3tick，越界成交首末时间至少相隔800毫秒，至少2笔，累计至少20手，才确认失守。品种预设会改变距离和手数。

由于1.1用“严格超过”，标准tick价格上，设3tick通常要到4tick才进入越界统计。价格回到未越界位置会清掉本轮失守累计；越界成交间隔超过5秒也会重新开始。1.1的首末时间差不等同于已经验证中间持续接受价格。

确认失守直接删除，过期区域也直接删除，不保留灰色旧对象。

## 9. 保留多久，为什么会变淡

- 普通区域默认90秒无新活跃证据就过期。
- 若出现成交停顿并随后向有利方向离开，形成结构证据，可以按最近结构证据保留1800秒。它不是从第一次形成起固定30分钟的硬上限；失守仍然提前删除。
- 默认先保持亮度30秒，然后用300秒逐渐降到25%可见强度。
- 淡化只改变外观，不延长寿命。普通区域可能先达到90秒无活跃过期条件，在完整淡化前就直接消失。
- 一个合并成员刷新不会让所有旧成员恢复满亮度。
- 断线后重新建立盘口快照会清除此前观察区域，不把旧快照当成当前证据。

## 10. 黄线合并、数量与文字

相邻、同侧且处于观察状态的区域可以合并。默认允许中间空2tick，合并宽度最多12tick，最多显示6个区域、4条说明。

优先照顾现价上下方最近的区域，其他主要按距离筛选。未画出的有效区域可能仍在内部跟踪；筛选主要依据位置和距离。

黄线从形成K线延伸到图表右侧。黑底文字固定在可见盘口栏左侧，右边缘统一对齐，默认留12像素间距；左右拖动时间轴时，文字的横向锚点不随K线移动。上下移动价格轴时，文字随对应黄线移动。文字实际宽度按内容收紧，最长380像素，过长显示省略号。原生DOM与已开启的独立栏都参与避让，关闭独立栏后仍避开原生DOM。说明空间不足、超出可见价格区域或与优先说明重叠时省略，不移到其他价位。很薄的区域按文字框中心对齐，不扩大价格范围。形成K线尚未进入可见历史时不会画出该区。

说明可能包含“增挂较多”“减量较多”“成交停顿”“已触及”“第几次回测”“已收回”“数据不足，暂停判断”等。读取时先看为什么形成，再看当前反应。当前黄线不是历史盘口回放；拖到过去看到的线，不证明当时已知有这个区域。

## 12. 常见问题

### 列表里找不到指标

检查是否下载了原始DLL而非GitHub网页，是否放进正确平台的自定义目录，是否重启平台，以及平台是否兼容当前.NET构建。先确认文件名为DepthOfMarketBeta.dll。

### 有盘口，但Net/Both暂时为空

初始快照只是基线。等待新的增减变化；检查P0及对应栏开关、距离是否移出屏幕、过滤量是否太高。刚到重置边界也会清零。四栏在最新K线位于可见区域右侧之外、以及盘口过期时会暂停绘制；先回到实时位置核对。

### 没有黄线

依次检查Z1总开关、Z4显示开关、实时Level2和成交数据、Z1黄线状态。活动不足、基线未就绪、新位置预热、合约价差超过限制或显示数量筛选，都可能让黄线为空。不要为出线立即把所有门槛降到最低。

### 显示盘口异常、暂停生成

Z1状态会给出具体原因：

- **盘口未更新**：显示距最后一次有效盘口更新多久、超时阈值。原生DOM也不更新时检查连接与交易时段；原生DOM持续变化而这里仍超时，应保留完整状态以便检查事件链路。
- **缺少买盘或卖盘**：当前内部盘口缺少一侧，不具备完整报价。
- **买卖盘交叉或锁定**：买一不低于卖一，当前内部报价不可用于区域判断。
- **价差超限**：显示实际价差、允许价差和买一卖一；在Z3检查品种预设及最大允许价差，不建议直接把门槛调到很大。

仅在真实盘口更新回调中，指标会限频核对异常报价与平台快照；发现完整、价差合格的快照才重建观察基线。快照不算增挂事件，校正后旧区域清除并重新预热，状态会记录盘口校正次数。定时器不会单靠反复读取快照延长数据的新鲜度。

后面的“合并0区/筛选0区/绘制0区”只表示当前没有可绘制区域，不是另一个绘图错误。

### 只有近端变化，没有想看的远端

检查最大观察距离和行情源真实推送的深度。扩大参数不会扩大行情权限。本指标不提供独立的近远端短时标签。

### 黄线有，文字没有

检查Z4形成原因开关、最多说明是否为0，以及黄线内是否有足够空间。其他说明占位时会省略文字。可调整说明最大宽度、说明距盘口栏的间距或显示数量。文字不会为了避让而移动到错误价位。

### 黄线还没淡完就消失

区域过期、失守或重连清除都会先于完整淡化生效。调整Z4淡化时间不会延长Z2的无活跃有效期。

### 更新后不是新默认参数

旧模板和图表实例会保留参数。重新添加并不套用旧模板，或手动核对宽100、Net距离150、Both距离300和配色。主图存在多个盘口实例也容易误认为更新没生效。

### 能不能用历史K线复盘挂撤单

不能仅凭历史K线或足迹重建历史挂撤单。本实现用实际收到的数据和本机UTC到达时间处理观察，不宣称已完成虚拟时钟盘口回放适配。历史图上的当前区域不能当作当时存在的入场信号。

## 13. 一个简单观察顺序

先看价格附近的Net/Both：增加和减少各有多少、净变化如何。再看黄线来自盘口活动还是成交停顿。价格进入后观察攻击成交是否能推动价格、有没有补量、最后向哪边离开。结合新鲜证据使用区域，失效或过期后停止参考已删除区域。

## 14. 升级与卸载

升级时备份旧DLL，关闭平台再替换，保留自己需要的模板。卸载时先从图表移除实例，关闭平台后移走DLL即可。本版不会调用指标授权服务器，也没有需要清理的激活码。
